# MediaPitch Ollama Proxy

Small PHP proxy for controlled access to Ollama Cloud.

## URLs

- User login/dashboard: `https://mediapitch.in/ollama-proxy/`
- Apply for access: `https://mediapitch.in/ollama-proxy/register`
- Admin: `https://mediapitch.in/ollama-proxy/admin`
- Chat API: `https://mediapitch.in/ollama-proxy/api/chat`
- Generate API: `https://mediapitch.in/ollama-proxy/api/generate`
- Embed API: `https://mediapitch.in/ollama-proxy/api/embed`
- Embeddings API: `https://mediapitch.in/ollama-proxy/api/embeddings`

## Required hosting environment variables

```text
OLLAMA_PROXY_APP_KEY=<base64 encoded 32-byte random key>
OLLAMA_PROXY_UPSTREAM_KEYS=<real Ollama Cloud key,or,multiple comma-separated keys>
OLLAMA_PROXY_ADMIN_PASSWORD=<long random admin password>
```

Optional:

```text
OLLAMA_PROXY_UPSTREAM_BASE_URL=https://ollama.com
OLLAMA_PROXY_DAILY_REQUEST_LIMIT=100
OLLAMA_PROXY_REGISTRATION_ENABLED=true
```

Generate the encryption key with:

```bash
php -r "echo base64_encode(random_bytes(32)), PHP_EOL;"
```

The real Ollama Cloud keys are only read from the server environment. Proxy users receive `mp_oll_...` keys generated by this application. The stored user key is encrypted for dashboard display and separately SHA-256 hashed for authentication lookup.

## Approval flow

1. User applies with email and password.
2. Account and proxy key are created disabled.
3. Admin opens `/ollama-proxy/admin`, signs in with `OLLAMA_PROXY_ADMIN_PASSWORD`, activates the user, and sets a daily request limit.
4. User logs in and sees the proxy key and recent usage.
5. API requests use `Authorization: Bearer mp_oll_...`.

## Example

```bash
curl https://mediapitch.in/ollama-proxy/api/chat \
  -H "Authorization: Bearer mp_oll_YOUR_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"glm-5.3:cloud","messages":[{"role":"user","content":"Hello"}],"stream":false}'
```

## Storage and limits

SQLite is stored at `ollama-proxy/data/proxy.sqlite`. The directory is denied by `.htaccess` and ignored by Git. Each request logs user, endpoint, model, HTTP status, request size, response size, and timestamp. The current quota is request-count based per UTC day.

## Security notes

- Never commit real Ollama Cloud keys.
- Use HTTPS only in production.
- Set a strong admin password.
- Keep the application encryption key stable after users are created; changing it makes existing encrypted dashboard API keys unreadable.
- Only explicitly whitelisted Ollama endpoints are proxied.
